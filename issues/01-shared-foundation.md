**What to build:** the shared ground every feature track stands on — the database, the typed domain vocabulary, working data stores (real + test), the UI primitives, and the global layout — so that after this ticket a developer on any track can read and write reports/users/notifications/private messages through a stable interface against seeded MIT data, and render inside the app shell, without touching another track's files. This is Wave 1 and must be DONE on `main` before anyone branches.

- [ ] Supabase schema (migrations) covers: campuses (with city-handoff config: city name, service URL, phone; plus campus police + counseling fields), buildings (with coordinates + floors), users (id, name, @mit.edu email, role, publicTeam?, privateOffice?), reports (public: category, item, title, tier, status, location, flags incomplete/location-unverified, photo URL, campusId, buildingId?, createdAt), co-signs (one per user per report), notifications (recipient, body, read, createdAt), private_reports (office/currentOffice, don't-share-name flag, status), private_messages (reportId, authorRole, authorId, body, createdAt), access_log (actor, action, reportId, createdAt), quick_fixes (campusId, category, item?, text), self_resolutions.
- [ ] `seed.sql` seeds the MIT demo campus to the scripted demo beats: ~12 buildings with coordinates + dining halls; demo users (students Ana/Ben/Cam + ~40 background co-signers; one responder per public team; private-office staff) with @mit.edu emails; ~40 historical reports including an OPEN Dining ice-cream-machine report at 14 signers, a High broken-handrail report (4 signers) and a Medium Wi-Fi-drops report (9 signers), enough Wi-Fi history to yield "~9 similar · ~3 days"; 2 direct reports (Housing + Title IX); curated quick fixes (incl. Wi-Fi reconnect); campus config with Cambridge SeeClickFix (cambridgema.gov/SeeClickFix, 617-349-4300), MIT Police 617-253-1212, counseling health.mit.edu.
- [ ] Shared domain types/enums exported from one place: Report, Tier (Low/Medium/High/Urgent), Category (Facilities/Dining/Housing/IT/Grounds/Safety/City), Office, Status (Received/Assigned/In progress/Fixed/Won't fix) and private statuses (Received/Reviewing/Resolved/Referred), User, Campus, Notification, PrivateReport, PrivateMessage, AccessLogEntry, QuickFix.
- [ ] Store interfaces for reports, users, notifications, access-log, campuses, private (reports + messages), quick-fixes — each with TWO implementations behind the interface: a Supabase-backed one for runtime and a deterministic in-memory/seed-backed one used by tests. Store is the single data seam.

- [ ] `components/ui` shadcn primitives (button, dialog with focus-trap, tabs, input, card, badge, select) accessible by default; tier color tokens as CSS variables meeting >=4.5:1 contrast; global `prefers-reduced-motion` handling in globals.css.
